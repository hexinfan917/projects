## 1. 功能概述

**犬格检测**是为宠物狗设计的性格与行为标准化测评工具，类似人类 MBTI / 性格测试。用户（主人）根据狗狗日常真实表现回答 24 道选择题，系统按四维双极模型计分并给出犬格编码、性格标题、行为画像及饲养 / 训练建议。

该功能作为小程序核心入口之一（首页「犬格检测」），既能帮助主人了解狗狗性格，也能为平台推荐合适路线、活动分组、保险等级等提供数据支撑。

## 2. 目标用户与场景

| 用户 | 场景 | 价值 |
|------|------|------|
| 养狗主人 | 带狗出行前，评估狗狗是否适合某类活动 | 避免应激、冲突、意外 |
| 潜在用户 | 注册后首次使用，快速建立宠物档案 | 增强粘性，了解平台专业性 |
| 平台运营 | 根据犬格结果做路线推荐、保险定价、分组管理 | 提升服务精准度 |
| 训犬师 | 查看测评报告，后续复核验证 | 作为行为评估参考 |

## 3. 核心流程

```
进入犬格检测（小程序首页入口）
   │
   ▼
已登录？
   ├─ 是 → 拉取已有宠物档案
   │        │
   │        ▼
   │      选择要测评的宠物（或新建临时宠物）
   │
   └─ 否 → 填写临时宠物信息（可答题，提交前引导登录）
   │
   ▼

   │
   ▼

   │
   ▼
查看结果报告
   │
   ▼
可分享报告 / 重新测评 / 返回首页
```

### 3.1 老用户流程

- 进入犬格检测时，若已登录，自动拉取当前用户的宠物档案列表
- 展示宠物选择页，支持选择已有宠物或「为其他宠物测评」
- 选择已有宠物后，使用 `pet_id` 关联测评记录

### 3.2 新用户流程

- 未登录用户可先填写临时宠物信息并答题
- 提交查看报告前，引导登录 / 注册
- 登录成功后，使用测评中填写的宠物信息自动创建宠物档案
- 档案状态标记为 `incomplete`，后续引导用户完善剩余字段

### 3.3 临时宠物信息转正式档案规则

| 测评字段 | 档案字段 | 转换规则 |
|----------|----------|----------|
| name | name | 直接写入 |
| breed | breed | 直接写入 |
| age_str | age_str / birth_date | 纯数字年龄自动计算 birth_date |
| gender | gender | 直接写入 |
| avatar | avatar | 有则写入，无则使用品种默认图 |
| - | profile_status | 固定为 `incomplete` |
| - | source | 固定为 `personality_test` |
| - | is_default | 固定为 0，不自动设为默认宠物 |

### 3.4 宠物档案互通原则

1. **测评是宠物档案的入口之一**，不是独立于档案的流程
2. **已有档案直接复用**，不让用户重复填写
3. **测评中新增的宠物信息，自动沉淀为档案**
4. **测评只收集档案必要字段**，缺失字段标记为「待完善」，后续引导补充

## 4. 测评题目结构

共 **6 大模块、24 道试题**，每题单选，按选项赋分。每道题的选项分值由管理后台配置，系统汇总各维度正负极得分并生成犬格编码。

### 4.1 模块划分

| 模块 | 主题 | 题号 | 满分 |
|------|------|------|------|
| 第一模块 | 陌生人耐受度（社交性格） | 1-3 | 9 分 |
| 第二模块 | 同类狗狗社交耐受度（犬际社交） | 4-6 | 9 分 |
| 第三模块 | 环境应激耐受度（胆量抗压） | 7-9 | 9 分 |
| 第四模块 | 资源占有护食行为（攻击性隐患） | 10-12 | 9 分 |
| 第五模块 | 主人服从与自控能力（随行服从） | 13-18 | 18 分 |
| 第六模块 | 分离情绪与居家行为（情绪稳定性） | 19-24 | 18 分 |

### 4.2 每道题结构

- 题干：描述一个具体场景
- 4 个选项（A/B/C/D），分别对应不同分值
- 每道题绑定一个犬格维度（EI / SN / FT / PJ）
- 每个选项配置：
  - `score`：分值（当前每题满分 3 分）
  - `polarity`：对维度正极或负极的贡献（`+` / `-`）
- 管理后台可配置选项文案、分值与极性；分值与极性共同决定四维得分

## 5. 计分与犬格编码规则

### 5.1 基础计分规则

- 每题选择一个选项，获得该选项对应 score
- 同一维度下的题目，按选项的 `polarity`（`+` / `-`）分别累加到正极得分和负极得分
- 通过比较每个维度正/负极得分率，判定该维度的倾向字母

```
维度正极得分率 = 该维度正极实际得分 / 该维度正极满分
维度负极得分率 = 该维度负极实际得分 / 该维度负极满分

若 正极得分率 >= 负极得分率，取正极字母；否则取负极字母
```

### 5.2 犬种特异性权重（可选，默认 1.0）

不同犬种的性格基准不同。例如金毛天性友好，柴犬独立性较强，工作犬服从性期望更高。系统支持按犬种分组设置模块权重。

```
加权模块得分 = 模块原始得分率 × weight × 模块满分
```

> 注：加权模块得分仅用于多维度的内部参考，不再用于单一总分评级。

### 5.3 犬格编码判定

系统采用**四维双极计分模型**，不再使用单一总分评级，而是根据四个维度的得分倾向生成 4 位犬格编码（类似 MBTI）。

#### 四维定义

| 维度 | 正极（得分高） | 负极（得分高） | 含义 |
|------|----------------|----------------|------|
| EI | E 外向 | I 内向 | 社交倾向：对陌生人/同类的主动程度 |
| SN | S 实感 | N 直觉 | 感官敏感：对环境刺激的反应模式 |
| FT | F 感性 | T 理性 | 情感需求：对主人的依赖与情绪表达 |
| PJ | P 随性 | J 计划 | 生活规律：服从性、自控力与作息偏好 |

#### 判定规则

对每个维度分别比较正极得分率与负极得分率：

```
正极得分率 = 正极实际得分 / 正极满分
负极得分率 = 负极实际得分 / 负极满分

若 正极得分率 >= 负极得分率，则取正极字母
否则取负极字母
```

四个维度依次判定，组合成 4 位编码，如 `ESFJ`、`INTP` 等，共 16 种结果。

#### 16 套犬格编码

| 编码 | 性格标题 | 编码 | 性格标题 |

### 5.5 结果解读维度

每份报告至少包含：
- **犬格编码与性格标题**：如 `ESFJ` +「贴心小棉袄」
- **性格描述**：一句话概括性格
- **行为画像**：根据答题选项提取的 1-3 条关键行为标签（问题行为优先，正向特质补充）
- **四维犬格解析**：EI / SN / FT / PJ 四个维度得分条 + 洞察文案
- **训练指南**：针对该犬格类型的训练建议卡片
- **推荐服务/活动**：基于犬格结果推荐的平台服务或活动
- **可信度评分**：基于答题行为计算

### 5.6 可信度评分

用于识别用户是否认真作答：
- 全部选择同一选项：扣 25 分
- 答题总时长过短（< 20 秒）：扣 25 分
- 选项分布严重偏态（某一选项占比 ≥ 80%）：扣相应分数
- 维度区分度过低（两极得分过于接近）：扣相应分数

```
reliability_score = max(0, 100 - 扣分合计)
```

报告页若 `reliability_score < 60`，提示「结果可信度较低，建议根据狗狗真实表现重新测评」。

- 每条规则对应：题目 ID + 选项 order → 一个标签
- 管理后台「行为画像配置」页简化为「按题目 - 选项写一句话」：
  - 每道题展开后显示 4 个选项
  - 运营人员在每个选项下输入一句话
  - 保存时，系统自动创建/更新对应的标签，并生成权重为 1、阈值为 1 的规则
- 数据模型仍保留标签/规则两层结构，便于后续扩展（如多题聚合、权重调整）

### 7.3.3 展示策略

1. 用户提交测评后，后端根据答案匹配所有命中的规则，按标签累计权重
2. 只展示满足阈值的标签
3. 标签分为两类：
   - `problem`：问题行为 / 需要关注的行为
   - `positive`：正向特质 / 优点
4. 最终展示顺序与数量：
   - 优先展示 `problem` 标签，最多 2 条
   - 若 `problem` 不足 2 条或存在 `positive`，补充 1 条 `positive`
   - 若完全没有 `problem`，最多展示 3 条 `positive`
   - 总计最多 3 条
5. 若未命中任何标签，展示默认兜底文案：
   - 「目前暂未表现出特别突出的行为倾向，性格比较均衡。」

### 7.3.4 默认文案规则

首期已补全全部 24 道题、96 个选项的默认行为画像文案。默认规则按选项顺序划分：

- **选项 0 / 选项 1**（得分较高、表现较好）：默认配置为 **正向特质**（`positive`）
- **选项 2 / 选项 3**（得分较低、表现较差）：默认配置为 **问题行为**（`problem`）

运营人员可在管理后台随时覆盖默认文案。

## 15. 邀请好友 PK

### 15.1 功能定位

在现有犬格检测报告的基础上，增加「邀请好友 PK」能力：
- 用户 A 完成测评后，可以把自己的报告作为「挑战书」分享给好友 B；
- 好友 B 进入小程序后，选择/添加自己的宠物并完成测评（如还没有报告）；
- 系统对比两份报告，生成「PK 结果页」；
- 双方可以看到两只狗狗在犬格类型、四维倾向、各模块得分上的差异与亮点。

首期通过 URL 携带两份 `result_id` 完成即时对比，实现成本低且可分享；同时为 PK 参与者持久化 PK 记录（`dog_personality_pk_records` 表），用户中心可查看「我的 PK 记录」。

### 15.2 核心流程

#### 邀请方（用户 A）流程

```
测评报告页
   │
   ▼
点击「邀请好友 PK」
   │
   ▼
生成分享卡片 / 微信分享消息
   │
   ▼
分享路径：/subpackage/dog-personality/pk/index/index?inviter_result_id={A的result_id}
```

#### 被邀请方（用户 B）流程

```
打开分享链接
   │
   ▼
未登录？→ 引导登录（登录后回到本页面）
   │
   ▼
PK 落地页：展示用户 A 的报告摘要（宠物名、头像、犬格编码、性格标题）
   │
   ▼
用户 B 选择/添加要比拼的宠物
   │
   ├─ 该宠物已有测评报告 → 直接进入 PK 结果页
   └─ 该宠物没有报告 → 进入答题页，答完后回到 PK 结果页
   │
   ▼
PK 结果页：展示 A vs B 的对比结果
   │
   ▼
可再次分享 PK 结果页
```

### 15.3 页面与交互

#### 报告页入口

- 在 `subpackage/dog-personality/result/index` 底部固定栏放置「邀请PK」按钮；
- 「邀请PK」使用微信原生分享能力（`openType='share'`），分享路径为 PK 落地页；
- 该按钮替换原「生成海报」按钮，与「历史报告」并列为底部两个统一样式的操作按钮；

#### PK 落地页（`pk/index`）

- 从 URL 读取 `inviter_result_id`；
- 调用后端接口获取邀请方报告公开摘要（宠物名、头像、犬格编码、性格标题、标签，不展示用户隐私信息）；
- 下方列出当前用户可用于 PK 的宠物：
  - 已有测评报告的宠物：显示「上次测评：{type_code} · {title}」；
  - 无报告的宠物：引导先去测评；
  - 「为其他宠物测评并 PK」入口：跳转到答题页并携带 `pk_inviter_result_id`。
- 用户选择/测评完成后，跳转到 `pk/result/index?a={inviter_result_id}&b={invitee_result_id}`（Taro 页面路径为 `/subpackage/dog-personality/pk/result/index`）。

#### PK 结果页（`pk/result/index`）

- 从 URL 读取 `a` 和 `b` 两个 `result_id`；
- 展示双方宠物信息、犬格编码、性格标题；
- 用雷达图/进度条展示四维犬格对比；
- 四维得分逐项对比（进度条 + 每维度胜者小标签）；
- 根据四维总分差异给出「略胜一筹」「碾压局」「势均力敌」等趣味结论；
- 底部按钮：「重新 PK」「返回首页」；右上角原生分享 PK 结果。

### 15.4 对比规则

#### 犬格编码展示

- 展示双方 `type_code`（如 `ESFJ` vs `INTP`）及对应 `title`；
- 展示四维犬格雷达图/进度条，直观对比 EI / SN / FT / PJ 倾向。

#### 总分胜负

- 对双方四维得分（`dimension_scores` 各维度 `score`）分别求和，总分高者获胜；
- 总分相同则比较可信度评分 `reliability_score`，高者获胜；
- 仍相同判为平局；
- 页面上展示四维逐项对比及每维度胜者标签。

#### 趣味结论

根据总分差判定：
- 平局：「势均力敌」
- 总分差 ≥ 10：「碾压局」
- 其余：「略胜一筹」

### 15.5 后端接口设计

#### 获取报告公开摘要

```
GET /api/v1/dog-personality/results/{result_id}/public
```

返回结果公开摘要：
- `id`
- `pet_id`
- `pet_name`
- `pet_avatar`
- `type_code`（犬格编码）
- `title`（性格标题）
- `dimension_scores`（四维得分）
- `reliability_score`（可信度评分，PK 平局时用于判定）
- `report_data`（公开摘要：不含详细解读全文，仅保留 PK 展示所需信息）
- `is_owner`（当前访问者是否为报告主人，未登录为 false；用于 PK 记录归属判断）
- `created_at`

#### 获取可 PK 的宠物列表

复用已有接口：

```
GET /api/v1/pets/simple/list
```

前端根据 `last_result_id` 判断宠物是否已有报告。

#### 提交测评

复用已有接口：

```
POST /api/v1/dog-personality/results
```

被邀请方完成测评后，用返回的 `result_id` 进入 PK 结果页。

### 15.7 权限与隐私

- 任何人通过链接可查看报告公开摘要；
- 不暴露用户 ID、手机号、详细解读全文；
- 报告所有者可以正常查看自己的完整报告；
- 仅 PK 任一方的报告主人才会持久化 PK 记录，第三方打开分享链接只读不写。
