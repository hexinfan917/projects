# 尾巴旅行 - 宠物领养中心模块产品需求文档（PRD）

## 一、项目背景与目标

### 1.1 背景
尾巴旅行作为宠物出行服务平台，用户群体以养宠人士为主。平台内存在大量有领养需求（想养第二只宠物）或有送养需求（因搬家、过敏等原因无法继续养宠）的用户。目前平台缺少连接送养人与领养人的官方渠道，导致用户自发在微信群、朋友圈发布领养信息，信息分散且缺乏信任背书。

### 1.2 目标
- 为平台用户提供安全、可信的宠物领养信息发布与浏览渠道
- 通过实名认证、领养协议、平台审核等机制建立信任体系
- 丰富平台公益属性，提升用户粘性与品牌好感度
- 与现有"小善行动"公益板块形成互补（小善行动偏活动/捐赠，领养中心偏宠物匹配）

### 1.3 需求范围
| 范围 | 说明 |
|------|------|
| **包含** | 领养列表、领养详情、发布领养、我的领养管理、收藏、分享、海报生成 |
| **不包含** | 送养人与领养人之间的 IM 即时聊天（第一期使用电话/微信线下沟通） |
| **不包含** | 领养申请审批流（第一期简化，点击"我要领养"即获取联系方式） |
| **不包含** | 物流/宠物托运（平台不涉及交易，仅提供信息撮合） |

## 三、用户角色与业务流程

### 3.1 用户角色

| 角色 | 说明 | 核心诉求 |
|------|------|---------|
| **送养人** | 因各种原因无法继续养宠，希望为宠物找到新家的用户 | 快速找到靠谱领养人，确保宠物被善待 |
| **领养人** | 想要领养宠物的用户 | 浏览真实宠物信息，安全高效联系送养人 |
| **平台运营** | 尾巴旅行运营人员 | 审核信息真实性，处理违规举报，维护社区氛围 |

### 3.2 核心业务流程

```
【送养流程】
用户进入发布页 → 填写宠物信息 → 上传照片 → 填写联系方式
→ 选择健康状态与领养要求 → 提交发布 → 平台审核（或免审直接上架）
→ 信息展示在列表页 → 领养人浏览并联系 → 线下完成领养
→ 送养人标记"已被领养" → 信息下架

【领养流程】
用户进入领养列表 → 浏览/筛选宠物 → 点击进入详情
→ 查看详细信息与领养要求 → 收藏/分享
→ 点击"我要领养" → 查看送养人联系方式
→ 电话/微信联系 → 线下见面 → 完成领养
```

## 四、功能详细需求

### 4.1 领养列表页

#### 4.1.1 页面概述
用户进入领养中心的首页，以卡片列表形式展示所有待领养的宠物信息。

#### 4.1.2 功能需求

| 需求ID | 需求描述 | 优先级 |
|--------|---------|--------|
| AD-LIST-001 | 顶部显示城市定位筛选，默认"全国"，点击可切换城市 | P1 |
| AD-LIST-002 | 城市选择器支持按省份-城市层级选择，或直接搜索城市名 | P2 |
| AD-LIST-003 | 列表以卡片形式展示，每张卡片包含：宠物封面图、名字、性别、年龄、已实名标识、描述摘要、状态标签（绝育/免疫/驱虫） | P1 |
| AD-LIST-004 | 列表支持下拉刷新、上拉加载更多（分页，每页10条） | P1 |
| AD-LIST-005 | 空状态：当没有领养信息时，显示"暂无待领养宠物" + 引导发布按钮 | P1 |
| AD-LIST-006 | 点击卡片进入领养详情页 | P1 |
| AD-LIST-007 | 支持按品种/是否免费筛选（第二期） | P3 |

### 4.2 领养详情页

#### 4.2.1 页面概述
展示单只宠物的完整领养信息，是用户决定是否领养的核心决策页面。

#### 4.2.2 功能需求

| 需求ID | 需求描述 | 优先级 |
|--------|---------|--------|
| AD-DET-001 | 顶部图片轮播区，支持多张宠物照片左右滑动，带指示点 | P1 |
| AD-DET-002 | 显示宠物名字 + 性别图标（♂蓝色/♀粉色）+ 年龄 | P1 |
| AD-DET-003 | 显示送养人"已实名"标识（完成实名认证的用户显示） | P1 |
| AD-DET-004 | 显示更新时间（如"1分钟前更新"、"3天前更新"） | P1 |
| AD-DET-005 | 显示所在城市 + 浏览量 + 收藏人数 | P1 |
| AD-DET-006 | 宠物详细描述区域，展示品种、性格、来源、送养原因等 | P1 |
| AD-DET-007 | 联系方式区域，显示送养人手机/微信，未点击"我要领养"前可部分隐藏（如 159****8663） | P1 |
| AD-DET-008 | 健康状态标签组：已绝育/未绝育、已免疫/未免疫、已驱虫/未驱虫、免费/收费 | P1 |
| AD-DET-009 | 领养要求清单，以勾选列表形式展示送养人预设的要求 | P1 |
| AD-DET-010 | 防骗提醒区域，固定文案提示用户谨防诈骗 | P1 |
| AD-DET-011 | 底部固定操作栏：收藏按钮、分享按钮、"我要领养"主按钮 | P1 |

| AD-DET-014 | 支持分享至微信好友/朋友圈（使用微信小程序原生分享） | P1 |

| id | BIGINT | 是 | 主键，自增 |

| pet_gender | TINYINT | 是 | 性别：1公 2母 |
| pet_age | VARCHAR(20) | 是 | 年龄描述 |
| pet_breed | VARCHAR(50) | 否 | 品种 |

| images | JSON | 是 | 图片URL数组，最多6张 |
| description | TEXT | 是 | 详细描述 |
| contact_phone | VARCHAR(20) | 是 | 联系电话 |
| contact_wechat | VARCHAR(50) | 否 | 微信号 |
| is_neutered | TINYINT | 是 | 是否绝育：0否 1是 |
| is_vaccinated | TINYINT | 是 | 是否免疫：0否 1是 |
| is_dewormed | TINYINT | 是 | 是否驱虫：0否 1是 |
| is_free | TINYINT | 是 | 是否免费：1免费 0收费 |
| price | DECIMAL(10,2) | 否 | 收费金额，默认0 |
| requirements | JSON | 否 | 领养要求数组 |
| status | TINYINT | 是 | 状态：0待审核 1已上架 2已下架 3已领养 |
| view_count | INT | 是 | 浏览量，默认0 |

**索引设计：**
- `idx_city_status`：联合索引(city, status)，用于列表筛选
- `idx_user_id`：普通索引(user_id)，用于我的发布查询
- `idx_status_created`：联合索引(status, created_at)，用于列表排序

### 5.2 领养收藏表（adoption_collections）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | BIGINT | 是 | 主键，自增 |
| user_id | BIGINT | 是 | 用户ID |
| adoption_id | BIGINT | 是 | 领养信息ID |
| created_at | TIMESTAMP | 是 | 创建时间 |

**索引设计：**
- `uk_user_adoption`：唯一索引(user_id, adoption_id)，防重复收藏
- `idx_user_id`：普通索引(user_id)，用于我的收藏查询

## 七、非功能需求

### 7.1 性能要求
- 领养列表接口响应时间 < 300ms（95分位）
- 图片加载使用 CDN + 懒加载，首屏图片压缩至 200KB 以内
- 列表页支持分页，避免一次性加载大量数据

### 7.2 安全要求
- 联系方式（手机号）在详情页默认部分隐藏，点击"我要领养"后才展示完整号码
- 发布内容需进行敏感词过滤（如虐待、贩卖等违规词汇拦截）
- 图片上传需进行内容审核（接入阿里云/腾讯云内容安全接口）
- 防止爬虫：列表接口增加频率限制（单IP 60次/分钟）

### 7.3 审核机制（第一期简化版）
- 默认免审直接上架，降低发布门槛
- 运营后台支持对已上架内容进行下架处理
- 用户可对违规内容进行举报
- 第二期可增加人工审核流程

### 7.4 兼容性
- 适配 iOS / Android 微信小程序
- 支持 iPhone 刘海屏、全面屏安全区适配
- 适配暗黑模式（如有需要，第二期支持）

## 八、运营后台需求（管理后台）

### 8.1 领养信息管理
- 列表展示所有领养信息，支持按状态、城市、时间筛选
- 支持单条/批量上下架、删除
- 查看详情（包含联系方式，方便运营联系送养人核实）

### 8.2 举报管理
- 展示用户举报记录
- 支持标记处理状态：待处理/已处理/已驳回
- 支持对违规内容进行下架/封禁操作
