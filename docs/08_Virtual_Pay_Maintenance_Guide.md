# 虚拟支付维护指南

## 一、价格修改流程

修改会员套餐价格时，**三个地方必须保持一致**：

```
尾巴旅行管理后台  ←→  数据库  ←→  微信虚拟支付后台
```

### 操作步骤

1. **尾巴旅行管理后台** → 会员管理 → 会员套餐 → 编辑 → 修改售价 → 保存
2. **微信虚拟支付后台** → 道具配置 → 找到对应道具 → 编辑 → 修改价格 → 保存 → 发布现网
3. **等待 5-10 分钟**（微信同步延迟）
4. 测试支付确认正常

> ⚠️ 价格单位：管理后台和微信后台都是「元」，代码自动转换为「分」（goodsPrice = 元 × 100）

---

## 二、新增会员套餐

新增套餐需要在微信虚拟支付后台创建对应道具：

### 操作步骤

1. **尾巴旅行管理后台** → 会员套餐 → 新建套餐 → 填写信息 → 保存
2. **获取套餐 ID**：保存后在列表中查看新套餐的 ID
3. **微信虚拟支付后台** → 道具配置 → 添加道具：
   - 道具类型：普通道具
   - 道具ID：`member_plan_{套餐ID}`（如 `member_plan_4`）
   - 道具名称：和套餐名称一致
   - 价格：和套餐售价一致（元）
   - 道具图片：200×200 PNG/JPG，<200KB
   - 关联关系：自定义
4. **保存 → 发布现网 → 等待 5-10 分钟**
5. **数据库绑定**：
   ```sql
   UPDATE member_plans SET product_id = 'member_plan_4' WHERE id = 4;
   ```
6. 测试支付

## 三、常见问题排查

| 错误码 | 错误信息 | 原因 | 解决方法 |
|--------|----------|------|----------|
| -15005 | `SIGNATURE_INVALID` | 用户态签名错误 | 重新登录小程序，获取最新 session_key |
| -15006 | `PAY_SIG_INVALID` | 商户侧签名错误 | 检查 OfferID、AppKey 配置 |
| -15013 | `GOODS_PRICE_INVALID` | 价格不匹配 | 检查管理后台、微信后台、数据库三者价格是否一致 |
| -15014 | `COIN_OR_PRODUCT_ID_CREATED_IN_RECENTLY` | 道具刚修改，未同步 | 等待 5-10 分钟后再试 |
| -15016 | `goodsPrice` 不接受浮点数 | goodsPrice 传了小数 | 代码已修复，确保 goodsPrice 为整数（分） |

## 五、发布检查清单

小程序上传审核前，确认以下事项：

- [ ] 会员购买入口已恢复（能看到价格、按钮）
- [ ] `wx.requestVirtualPayment` 已正确接入
- [ ] 微信虚拟支付道具已发布到现网
- [ ] 管理后台价格 = 微信后台价格 = 数据库价格
- [ ] 测试支付能正常调起并完成
- [ ] 支付成功后会员自动开通

## 六、接口文档

### 后端虚拟支付接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/pay/virtual/create` | POST | 创建虚拟支付订单，返回 signData/paySig/signature |
| `/api/v1/pay/virtual/confirm` | POST | 前端支付成功后调用，确认并开通会员 |
| `/api/v1/pay/virtual/notify` | POST | 微信服务器回调（兜底） |

### 前端调用

```js
wx.requestVirtualPayment({
  signData: '...',   // 后端返回
  paySig: '...',     // 后端返回
  signature: '...',  // 后端返回
  mode: 'short_series_goods',
  success: () => { /* 调用 /api/v1/pay/virtual/confirm */ },
  fail: (err) => { /* 处理错误 */ }
})
```
